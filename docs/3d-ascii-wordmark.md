# How the 3D ASCII wordmark works

`wordmark.svg` is the word **NANDHU** extruded into a 3D slab, rasterized to
ASCII characters, wiping in left to right and then rocking on its vertical
axis. It is one SVG with no JavaScript, generated by
[`scripts/make_wordmark_svg.py`](../scripts/make_wordmark_svg.py).

## The constraint

Images in a README land in an `<img>` tag, and an SVG loaded that way runs in
restricted mode — no scripts, no external resources, no interaction. It does run
[SMIL](https://developer.mozilla.org/en-US/docs/Web/SVG/SVG_animation_with_SMIL),
the declarative animation elements in the SVG spec.

So nothing can be rotated per frame. Every frame that will ever be shown has to
be rendered ahead of time and declared. The wordmark is a flipbook.

That is cheaper than it sounds: twenty frames of a 160×25 character grid is
still well under 100 KB of text before gzip, because blank rows and edges are
trimmed from every frame.

## Pipeline

| Stage | What happens |
| --- | --- |
| `build_shell()` | Draw the word with a bold TTF, threshold to a binary mask, extrude into a surface point cloud |
| `project()` | Rotate by yaw + tilt, back-face cull, perspective divide, Lambert shade + depth fog |
| `fit()` | One scale and offset that boxes every frame; derives the row count from the union bbox |
| `rasterize()` | Z-buffer splat into a `ROWS × COLS` character grid |
| `emit()` | Write the frames as SVG text rows, cycled by a discrete opacity animation |

### The surface shell

A solid extrusion would be wasted work — only the surface is ever visible. Three
sets of points, each carrying an outward normal:

- **Front and back caps** — every filled mask pixel at `z = -0.6` and `z = depth`,
  normals `(0, 0, -1)` and `(0, 0, 1)`.
- **Side walls** — boundary pixels (filled, with at least one empty 4-neighbour)
  repeated through the depth. The normal comes from which neighbours are empty,
  so a left edge gets `(-1, 0, 0)` and a corner gets the normalized diagonal.

No mesh library and no triangles. Points and normals are all a splatting
rasterizer needs.

### Shading

Brightness is Lambert against a fixed light, times a depth-fog term, indexed into
a density ramp:

```
RAMP = " .`:-=+*csS#%@"        # sparse/dim -> dense/bright
```

The z-buffer is one line, because painter's algorithm is free when you can sort —
order far to near and let NumPy's fancy assignment overwrite:

```python
order = np.argsort(-z)                     # far -> near, nearest wins
grid[row[order], col[order]] = idx[order]
```

### The SMIL flipbook

Each frame is a hidden `<g>` given its own slice of the loop. `calcMode="discrete"`
snaps between values instead of interpolating, so frames hard-cut instead of
cross-fading:

```xml
<animate attributeName="opacity" calcMode="discrete"
         values="0;1;0" keyTimes="0;0.35;0.40"
         dur="5.00s" begin="1.60s" repeatCount="indefinite"/>
```

Every group shares the same `dur`, and frame *i* owns `[i/n, (i+1)/n]`, so they
tile the loop with no gaps. The intro wipe is a separate animated `clipPath` that
freezes at full width and hands over.

## Things that bite, and why the constants are what they are

Each of these looks like a rendering fault and is really a scene-parameter
problem. A character grid is an extremely low-resolution display and it punishes
settings that would be invisible at pixel resolution.

**~25 grid columns per letter, minimum.** At a readable cell size each letter
needs roughly 25 columns; go narrower and the counters and letter gaps drop to
one or two columns — narrower than the sideways offset the rotation gives the
extrusion walls. The walls fill every hole and the word renders as one solid
brick. NANDHU is six letters, so it is stacked as two lines of three (`NAN` over
`DHU`) on an 85-column grid, keeping the panel half-width beside the portrait
while every letter still gets its ~25 columns. `TRACKING`
widens the gaps faster than the strokes, and `DEPTH_FRAC` caps how far the
walls can reach.

**`front` sits at `z = -0.6`, not `0`.** The side walls also start at `z = 0`, so
cap and wall points tied in the z-buffer and which one won came down to array
order — the letter faces came out streaked with wall-shaded pixels. Biasing the
cap 0.6 mask-pixels proud makes it win every tie. Walls still show past the
silhouette, where they belong, because yaw shifts them clear of the cap footprint.

**`CAM_DIST = 6.0`, `TILT_DEG = 4.0`, swing ±11°.** With a closer camera (3.4) the
far letter projects noticeably smaller than the near one at the ends of the
swing, and a steep tilt slants the baseline across the word, so the bottom row
frays to a two-character sliver. Backing off flattens the projection toward
isometric and keeps the baseline level. Nothing is lost — the extruded side walls
were always what sold the depth.

**Light keyed near the view axis** (`LIGHT = (-0.15, -0.45, -1.0)`). Conventional
upper-left lighting makes the extrusion walls brighter than the letter faces, and
the glyphs dissolve into edge highlights. Keying toward the camera keeps faces
solid and dense while walls fall away dimmer. That contrast gap is the 3D read.

**Arial Bold.** Even stroke weight shades consistently across a letter. Very
heavy faces (Impact) have counters that shrink below one grid cell and
disappear, so letters become blobs with notches. On this Windows machine the
face lives at `C:\Windows\Fonts\arialbd.ttf` (a plain `.ttf`, so the face index
is `0`); any bold TTF with even strokes will do.

## Regenerating

Only needed if the text, font or framing changes — the file is static and the
daily workflow does not touch it.

```powershell
pip install -r scripts/requirements.txt
python scripts/make_wordmark_svg.py --mode rock --out wordmark.svg
```

Modes: `rock` (gentle oscillation, in use), `once` (one full turn then freeze),
`spin` (continuous turntable), `static` (frozen frame, for eyeballing).

| Env var | Default | Purpose |
| --- | --- | --- |
| `WORDMARK_TEXT` | `NAN\nDHU` | `\n` splits lines |
| `WORDMARK_FONT` | `C:/Windows/Fonts/arialbd.ttf` | any TTF/TTC |
| `WORDMARK_FONT_INDEX` | `0` | face within a `.ttc` |
| `WORDMARK_TILT` | `4.0` | X tilt, degrees |
| `WORDMARK_COLS` | `85` | grid width; panel is `COLS × 9 + 36` px |
| `WORDMARK_ROW_MARGIN` | `3` | blank rows top and bottom |

Two sizing rules worth keeping:

- **Keep the downscale mild.** The panel is 801px wide natively and shown at
  478px in the README — about 1.7×. Rendering much larger and letting the
  browser scale it down further softens the glyphs into mush; stacking the
  six-letter word on two lines is what keeps the grid this narrow.
- **`ROW_MARGIN` is the height knob.** `fit()` derives the row count from the art
  so the panel hugs it; the margin pads it back out. At 3 the panel is 650px
  tall, which lands within a few px of the portrait beside it at README widths
  (478 vs 370), so the two windows read as a pair. Change the portrait's width
  and this is what you re-tune.
